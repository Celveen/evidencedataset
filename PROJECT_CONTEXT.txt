1. Goal And Pipeline
--------------------
EvidenceTree builds step-level PRM/SFT-style training data from multimodal VQA.

Pipeline:
1. Step 1: Qwen2.5-VL policy model runs MCTS and writes trajectories.
2. Step 2: each step gets local grounding plus tree-level outcome credit.
3. Step 3: DeepSeek generates rationales explaining labels.
4. Step 4: quality filter writes train/val JSONL.

Main code areas:
- Dataset pipeline: DatasetConstruct/
- Actions/retrievers: src/evidencetree/actions/
- MCTS: src/evidencetree/mcts/
- PRM scoring/rationale: src/evidencetree/prm/
- Benchmark loading/metrics: src/evidencetree/eval/
- Testing guide: DatasetConstruct/TESTING_GUIDE.md

4. Current Actions
------------------
MCTS action types:
- text_search(query)
- image_search(image/region)
- text_to_image(query), opt-in cross-modal
- image_to_text(image/region), opt-in cross-modal
- ocr(image/region), optional
- answer(text)

text_search:
- Uses BM25 for ordinary local corpus.
- Returns text snippets/documents.

image_search:
- For MRAG/local image corpora: CLIP FAISS image retrieval.
- It is image-only retrieval: query image -> visually similar Top-K.
- It does not use question text to rerank or disambiguate.
- Qwen is not scanning the full image corpus; it only sees returned evidence.

text_to_image / image_to_text:
- Synced from upstream Celveen/EvidenceTree on 2026-06-19.
- Implemented locally as opt-in cross-modal actions behind
  retriever.cross_modal=true.
- Backed by CrossModalCLIPRetriever with separate image and text sub-indexes.
- text_to_image: text query -> corpus images.
- image_to_text: query image/region -> corpus text docs.
- Default remains retriever.cross_modal=false, so current pipeline behavior is
  unchanged unless explicitly enabled.

ocr:
- Generic optional MCTS action, not the old SlideVQA/M3DocVQA adapter.
- Controlled by retriever.ocr.enabled.
- Uses project-local Tesseract:
  /home/wenke/SQJ/code/EvidenceTree/.tools/tesseract/bin/tesseract
- Current configs have OCR enabled, but for InfoSeek it often hurts.
- OCR is not a Top-K retriever; it returns one OCR text observation.
- Step 2: local_grounding=null, score=outcome_credit,
  score_source=outcome_only, label_weight=1-alpha.

answer:
- Terminal action.


5. Step-Level Scoring
---------------------
For steps with a local score:
  score = alpha * local_grounding + (1 - alpha) * outcome_credit

Default:
  verifier.alpha = 0.5

local_grounding:
- text_search: lexical overlap between search query and question.
- text_to_image: lexical overlap between search query and question.
- image_search: CLIP image-text alignment when verifier.image_backend=clip.
- image_to_text: CLIP image-text alignment when verifier.image_backend=clip;
  otherwise neutral 0.5.
- ocr: null.
- answer: null.

outcome_credit:
- Tree-level credit.
- For each query/action-prefix node, average outcome correctness of all
  trajectories passing through that prefix.
- This avoids assigning one final reward uniformly to every step.

Important metric fix:
- InfoSeek sometimes stores numeric gold as a dict string with a range, e.g.
  {'wikidata': 153.0, 'range': [137.7, 168.3]}.
- src/evidencetree/eval/metrics.py now treats a numeric prediction inside the
  range as correct, e.g. "150 g" is correct for that label.
- To propagate this into Step 2 outcome_credit, rerun Step 1/full pipeline,
  because trajectories store outcome_em from Step 1.

8. Image Search Diagnosis
-------------------------
Standalone diagnostic script:
  DatasetConstruct/diagnose_image_search.py

Run:
  PYTHONPATH=src .venv-qwen25vl/bin/python \
    DatasetConstruct/diagnose_image_search.py \
    --config DatasetConstruct/config.qwen25vl.yaml \
    --datasets mrag_bench crag_mm \
    --n 5 --top-k 5 \
    --pipeline-root data/pipeline_5q \
    --output data/image_search_debug/report.html

Visual report:
  data/image_search_debug/report.html

Diagnosis notes:
  data/image_search_debug/README.md

Findings:
- InfoSeek/ScienceQA are not tested by image_search diagnosis because their
  active corpora have no corpus images.
- MRAG-Bench image retrieval is mostly visually reasonable, but corpus entries
  are unlabelled. Evidence text often says only:
  "Unlabelled image from the MRAG-Bench retrieval corpus."
  Therefore Qwen must actually inspect returned images.
- CRAG-MM image retrieval is less stable. It is pure image-only retrieval and
  can return visually similar but wrong entities, especially cars/SUVs.
  Example: Chevrolet Trailblazer query retrieved Jeep Grand Cherokee,
  Chevrolet Silverado, Kia Telluride, GMC Terrain, Kia Carnival.
- CRAG examples where image_search is fine but final scoring is hard:
  yellow roses, cell towers, AirPods/headphones.

Likely future fix:
- Add question-aware reranking after image_search:
  image Top-K/Top-20 + question text + retrieved metadata -> reranked evidence.
- For CRAG vehicle/model questions, do not trust image-only Top-1 as the final
  entity decision.
- Cross-modal actions are now wired locally, but still opt-in. They may help
  MRAG/ScienceQA-style cases only when the corpus modality supports them.

Useful overrides:
- Cheap mock check:
  --set policy.backend=mock --set rationale.backend=mock
- Use Qwen but avoid DeepSeek cost:
  --set rationale.backend=mock
- Only run MCTS and scoring:
  --steps 1,2
- Only rerun rationale/filtering:
  --steps 3,4 --force
- Disable OCR:
  --set retriever.ocr.enabled=false
- Disable image_search:
  --set retriever.image.enabled=false
- Enable upstream-style cross-modal actions:
  --set retriever.cross_modal=true

  --set verifier.image_backend=neutral

15. Old Action Space Failure Analysis
-------------------------------------
Run date: 2026-06-21
Question:
  Whether the old action space alone has problems it structurally cannot solve.

Old action space:
  text_search, image_search, answer
  OCR off
  cross_modal false

Report:
  data/old_action_space_failure_analysis.md

Findings:
  Old action space is not fundamentally broken, but it has structural limits.
  On the larger comparison run, old-failed/new-solved counts were:
    infoseek: 7 queries
    scienceqa: 2 queries
    mrag_bench: 4 queries

Concrete failure types:
  1. Visual deictic entity resolution:
     Example infoseek_val_00039755 asks "Which diocese does this building
     belong to?" Old text_search retrieves generic/distractor church pages
     because it cannot map the query image to the building identity. New
     cross-modal path reaches Basilica of Our Lady of Lujan, then answers
     Archdiocese of Mercedes-Lujan.

  2. Weak image/entity grounding:
     Example infoseek_val_00019262 asks aircraft country of origin. Old
     text_search partially retrieves Embraer EMB 120 Brasilia but answers
     Slovakia. New image_to_text makes the aircraft identity more salient and
     answers Brazil.

  3. Fine-grained visual classification over unlabelled visual corpus:
     MRAG examples mrag-22 and mrag-3. Old image_search returns visually similar
     but unlabelled images, so the evidence lacks class/spec labels. New
     text_to_image/image_to_text can use option text and visual evidence to
     reach correct labels/specs.

  4. Reasoning failures are not solved by action-space changes:
     ScienceQA example scienceqa-smoke-14. Old text_search already retrieves the
     correct context, but Qwen chooses the wrong ratio. This needs better
     reasoning/prompt/verifier, not necessarily cross-modal actions.

Conclusion:
  Keep old action space as the cheap/clean default. Selectively enable
  cross-modal actions for visual deictic references, fine-grained visual
  classification, or option-text-to-image matching. Do not enable cross-modal
  for pure text reasoning cases where text_search already retrieves the needed
  context.


16. Current Recommendation
--------------------------
Current default config status:
  DatasetConstruct/config.qwen25vl.yaml has retriever.ocr.enabled = false.
  DatasetConstruct/config.qwen25vl.yaml has retriever.cross_modal = false.

Recommended operating mode:
  Keep OCR off by default. OCR is useful as an optional/gated action, but recent
  tests show it often produces empty/noisy text and increases step count.

  Keep cross_modal off by default for cheap/clean collection. Enable the new
  text_to_image and image_to_text actions only when a dataset/sample likely
  benefits from cross-modal retrieval.

Action-space conclusion:
  New cross-modal actions improve query-level success on supported datasets, and
  the improvement became clearer in the larger run. The cost is much higher
  collection time, about 3.84x more supported step-level samples, and lower
  rationale QC. The next engineering step should be action gating/prior routing,
  not simply enabling all actions globally or increasing rollout blindly.

CRAG-MM note:
  CRAG-MM currently ignores cross_modal=true because it uses official separate
  web and image indexes. Its MCTS still runs with text_search, image_search, and
  answer, but not with text_to_image/image_to_text.


17. Gate Strategy Experiment, N=30, Rollout=5
--------------------------------------------
Purpose:
  Test whether runtime action gating can keep the benefits of the new
  cross-modal action space while reducing collection cost.

Run setting:
  OCR off, rollout=5, requested n=30 per dataset.
  Actual samples: infoseek 30, scienceqa 25, mrag_bench 25, crag_mm 25.
  Gate runs executed step1/step2 only, so rationale QC is not measured for the
  gate modes.

Report:
  data/pipeline_30q_r5_gate_comparison.md

Summary over supported cross-modal datasets
  Supported datasets = infoseek, scienceqa, mrag_bench.

  old actions:
    EM 0.512, soft 0.550, mean F1 0.512, steps 334, cost 1.00x

  full new actions:
    EM 0.650, soft 0.662, mean F1 0.535, steps 1282, cost 3.84x

  dataset gate:
    EM 0.613, soft 0.688, mean F1 0.546, steps 892, cost 2.67x

  heuristic gate:
    EM 0.600, soft 0.650, mean F1 0.528, steps 807, cost 2.42x

  strict gate:
    EM 0.575, soft 0.625, mean F1 0.543, steps 801, cost 2.40x

Conclusion:
  dataset gate is the best default in this run. It keeps most of the new
  action-space benefit while cutting supported step count by about 30.4%
  compared with full new actions.

  heuristic gate is the cheaper fallback when runtime matters more than the
  last few correct queries.

  strict gate is useful mainly for smoke tests; it is too narrow as the default
  because it loses InfoSeek query-level accuracy without saving much more than
  heuristic gate.

Recommended default for larger collection:
  --set retriever.cross_modal=true
  --set retriever.ocr.enabled=false
  --set action_gate.enabled=true
  --set action_gate.mode=dataset
  --set action_gate.max_actions=5

Cost-sensitive alternative:
  --set action_gate.mode=heuristic
  --set action_gate.max_actions=4

CRAG-MM note:
  CRAG-MM still ignores cross_modal=true because it uses separate official
  web/image indexes. Gate testing on CRAG-MM mainly limits old actions, not the
  new text_to_image/image_to_text actions.

25. Prompt-Level Retrieval Query Guard
--------------------------------------
Date:
  2026-06-24

Goal:
  Use the upstream GitHub policy for Qwen-generated retrieval queries: allow
  useful query reformulation, but instruct Qwen not to invent an unidentified
  entity or drift away from the original question.

Configuration:
  DatasetConstruct/config.qwen25vl.yaml:
    policy.freeze_action_queries: false

Behavior:
  - Qwen may generate concise text_search/text_to_image query reformulations.
  - Generated queries are no longer replaced by the original question merely
    because they are not an exact copy.
  - The proposer prompt forbids assuming a concrete entity identity that has
    not been established by the image or evidence.
  - For an unidentified visual entity, the prompt asks Qwen to use visual
    retrieval before searching for entity-specific attributes.
  - Queries must remain faithful to the original question's intent.

  The old exact-copy implementation remains available behind
  freeze_action_queries=true for optional controlled experiments, but it is
  not enabled in the active Qwen configuration.

Verification:
  The proposer test verifies that a grounded reformulation is preserved and
  that the upstream anti-fabrication instructions are present in the prompt.

Scope:
  No grounding/local-score, CLIP similarity, gate, OCR, retriever, or action
  execution logic was changed by this update.


26. Local Grounding Scores Use Retrieved Evidence
-------------------------------------------------
Date:
  2026-06-23

Reason:
  The previous local grounding score for text_search only measured lexical
  overlap between the original question and the action query. With frozen
  queries, this made many text_search steps receive local=1.0 even when their
  retrieved evidence was unrelated.

Change:
  src/evidencetree/prm/data_gen.py now passes each step's current
  observation_evidence into GroundingVerifier.

  src/evidencetree/prm/verifiers.py now scores local grounding as:
    - text_search: max token-F1 between the action query and this step's
      retrieved evidence title+text.
    - image_search/image_to_text/text_to_image: calibrated CLIP retrieval score
      from this step's returned evidence when available.
    - answer/ocr: unchanged, local=None and outcome-driven.

Verification:
  Unit tests pass with external pytest plugins disabled:
    100 passed

  Re-scored data/pipeline_5q_infoseek_freeze_query.
  Example:
    infoseek_val_00067013#t2#s1 previously had local=1.0 because the query
    exactly matched the original question. After the change, its retrieved
    evidence was unrelated, so local=0.0667 and score=0.5333.

Entity-level dedup recall:
  The current index is document-level. Since one EVQA entity is split into
  multiple Wikipedia section docs sharing the same image, the same wrong entity
  can occupy many top-k positions. After deduplicating retrieved docs by entity:

  doc-level recall:

Interpretation:
  Deduplicating entities helps because it prevents repeated sections of the
  same wrong entity from filling top-k. However, even entity-level @100 is only
  39/100, so the larger problem remains: general CLIP does not robustly map
  iNaturalist observation photos to exact Wikipedia biological entities.

Gold-image availability split:
  all:
    R@1 11/100, R@50 23/100, top1 genus match 19/100
  gold_has_image:
    R@1 11/82, R@50 23/82, top1 genus match 19/82
  gold_no_image:
    R@1 0/18, R@50 0/18, top1 genus match 0/18

Conclusion:
  E-VQA's poor performance is not mainly because corpus images are missing.
  Missing gold images explain 18% of sampled failures, but even when gold images
  exist, R@50 is only 28.0%. The core issue is fine-grained species/entity
  grounding: CLIP often retrieves visually similar but wrong plants, birds,
  insects, fungi, or trees. A secondary issue is document-level duplication
  from multiple Wikipedia sections per entity.

Practical fixes to consider:
  1. Return entity-deduplicated image_search results for EVQA or for all
     entity-centric corpora.
  2. Build an entity-level CLIP index rather than section-level image vectors.
  3. Use a biology/iNaturalist-oriented image encoder such as BioCLIP or an
     iNaturalist-trained CLIP model for EVQA.
  4. Keep text_search after image_search, but do not expect text_search to
     recover if the first image step selected the wrong entity.
